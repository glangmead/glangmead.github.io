Balancing background, AI prompting, and coding exercises The background material is the prompting curriculum. A prompt is a spec, and a non-coder’s spec is only as good as their vocabulary (“a single-page website, no login, that reads an uploaded CSV and shows a sortable table”). The information-architecture exercise and the prompt-writing exercise are the same exercise. Hand-coding exists so students can read what the AI hands back: find the entry point, recognize a loop, see where data goes in, know which line to change. Reading, tracing, and modifying over writing from a blank file. Rough split, interleaved within every session: ~35% background, ~45% building with AI (the first ten minutes of which is writing the description before touching an assistant), ~20% reading and tweaking code by hand. One 90-minute rhythm: 25 min concept → 15 min describe the thing we’ll build → 35 min build with AI → 15 min read the result together and change one line. Python in Colab as the hands-on track (zero setup, everything on one screen, “cells run top to bottom” is the simplest answer to “why does this run”); Xcode as a live demo for the kinds-of-software and where-does-it-start pillars. Swap to Swift Playgrounds for the last sessions if the group turns out to be all-Mac and app-motivated. Course notebooks can live in a GitHub repo, edited locally (Claude Code can edit .ipynb files directly) and opened by students via https://colab.research.google.com/github/<user>/<repo>/blob/main/<notebook>.ipynb links.
