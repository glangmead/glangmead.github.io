1. What kinds of software are there?

  • Software Engineering for Vibe Coders: Frontends + Backends (Technically, Aug 2026) – written for non-technical people who build with AI tools; restaurant analogy (dining room = frontend, kitchen = backend/API/database). Part 1 of a 6-part series. The rest of Technically is a glossary and newsletter “making practical sense of software” for non-engineers.
  • Web apps vs native apps vs hybrid apps (AWS) – lay-readable, with a comparison table. Covers the how it’s delivered axis.
  • Introduction to Web Development (The Odin Project) – front-end vs back-end vs full-stack, and what kind of developer works on which part.
  • Client-server overview (MDN) – the cleanest written explanation of “static site” versus “site that needs a server and a database.”
  • Web Architecture 101 – one annotated diagram of a real company’s stack (DNS, load balancer, app servers, database, cache, CDN). Read the first half.
  • Automate the Boring Stuff with Python, 3rd ed. (free) – Part II is what “a script” means in the landscape of software. Chapter 0 defines “what is a program” and has a section titled “AI Won’t Replace Programmers.”
  • 2026 vibe coding tool comparison – a non-engineer builds the same dashboard in Replit, v0, Lovable, and Bolt. Useful for seeing “a website with a database” appear from a prompt.

2. Seeing how a piece of software is structured

  • How to Make Sense of Any Mess (Abby Covert; full text free) – information architecture “for everybody.” Seven short chapters with exercises; IA is “the way we arrange the parts of something to make it understandable.”
  • Information Architecture: Study Guide (Nielsen Norman Group) – start with “The Difference Between IA and Navigation,” “IA: 3 Key Models,” and “IA vs. Sitemaps.”
  • The C4 model – the Context and Container diagrams (“the iOS app, the API, the database”) are exactly the two pictures a non-coder can draw for any product. Stop before Components.
  • Chrome DevTools: viewing and changing the DOM – interactive, beginner-friendly. “Inspect element” on a site you know is the fastest way to see structure. Overview of the panels: Elements = structure, Network = what the page fetched.
  • Accessibility Inspector (Xcode) – plus Xcode’s Debug View Hierarchy: screens are trees of views.
  • Mobbin (free tier) – hundreds of thousands of real app screens organized by user flow. Study the structure of real apps without installing them.
  • The Design Process (Code.org CS Discoveries, Unit 4) – paper prototypes and user flows, with templates.
  • Jesse James Garrett’s Elements of User Experience five-plane diagram (strategy → scope → structure → skeleton → surface) – “structure” sits between “what it does” and “what it looks like.” (Site was down when checked; the diagram is widely mirrored.)

3. How computers and the internet work

  • How Computers Work (Code.org, Bill Gates et al.) – six 4–6 minute videos: what makes a computer a computer, binary, circuits and logic, CPU/memory/input/output, hardware and software. About 30 minutes total.
  • How the Internet Works (Code.org, Vint Cerf et al.) – ~8 videos: wires, IP and DNS, packets and routing, HTTP and HTML, encryption.
  • CS50x Week 0 (Harvard) – one two-hour lecture from “what is computer science” through binary/ASCII/Unicode/RGB, abstraction, algorithms, pseudocode. The best model of a “how computers represent things” session for adults.
  • CS50’s Understanding Technology – retired 2024 but archived and free; lectures on Hardware, Internet, Multimedia, Security, Web Development, Programming, aimed at “students who don’t consider themselves computer persons.”
  • Crash Course Computer Science – episodes 1–8 (early computing → CPU) and 29–30 (Internet, WWW). 10–12 minutes each, fast.
  • Wizard Zines comics (Julia Evans) – free one-page comics on HTTP, DNS, processes, memory, files and permissions. The zines themselves are paid.
  • How the web works (MDN).
  • How Does the Web Work? (The Odin Project) – curated videos ending with a knowledge check: “describe a Google search using the new vocabulary.”
  • What happens when you type google.com – the exhaustive answer, keypress to pixels. Use the section headings as a whiteboard outline.
  • The Unix Shell (Software Carpentry) – first two episodes are the gentlest “what is a file, a directory, a path, a command.”
  • The Internet (Code.org CS Principles, Unit 2) – lesson plans including an unplugged “Building a Network” activity and a browser-based Internet Simulator.
  • Computers (Khan Academy) – short articles on components, files and file sizes, logic gates. Good homework reading.
  • Going deeper: But How Do It Know? (J. Clark Scott; paid book, from a NAND gate up), Nand2Tetris, Ben Eater’s 8-bit breadboard computer.

4. Where does the code start?

  • Entry Point (main()) and Program Structure (Franco Garcia) – the entry point in ten languages, and the key distinction: some languages start at the first line, others require main().
  • Python: __main__ — Top-level code environment (official) and the gentler Real Python version.
  • Notebooks: What is the Jupyter Notebook? – cells plus a kernel. A notebook has no main(); the entry point is the cell you run. Google Colab is the zero-install way to use one.
  • Web: Next.js project structure – every file create-next-app makes, and the rule that app/page.tsx is the home page and layout.tsx wraps it. This is the “your code goes HERE” page for the web.
  • iOS: Understanding the basic structure of a SwiftUI app – @main → App → WindowGroup → ContentView. Also Build an iOS app with SwiftUI (swift.org).
  • Browser-based environments that skip setup: Replit (scripts, plus its AI agent), StackBlitz and CodeSandbox (web scaffolds). Glitch shut down hosting in July 2025.
  • Python Tutor – step through a program and watch its memory change, now with an AI that explains the diagram rather than solving the problem.

5. Coding with the help of AI

  • Not all AI-assisted programming is vibe coding (Simon Willison) – short, defines the distinction, and ends with a concrete list of rules for beginners: low stakes only, watch secrets and data privacy, set billing limits, get a review.
  • Here’s how I use LLMs to help me write code (Willison) – “the one thing you absolutely cannot outsource to the machine is testing that the code actually works.”
  • Speaking things into existence (Ethan Mollick) – a non-programmer builds a 3D game with Claude Code, then articulates the “minimum viable knowledge” needed to direct, judge, and troubleshoot.
  • The original “vibe coding” post (Andrej Karpathy, Feb 2025) – show it once, then Willison’s correction.
  • Vibe Coding: What It Means for Learning to Code in 2026 – practitioner’s distinction between AI-assisted learning and vibe coding, with breakage stories.
  • Learn AI-Assisted Python Programming, 2nd ed. (Porter & Zingaro, Manning 2024; paid) – “If you can move files around on your computer and install new programs, you can learn to write useful software.” No prior programming; AI assistant from page one; reading code and decomposing problems before writing.
  • AI Python for Beginners (Andrew Ng; free) – 11.5 hours, four modules, with an in-browser chatbot at your elbow. The best free course-shaped example of the premise.
  • Anthropic Academy – free self-paced courses: “Claude 101,” “AI Fluency,” “AI Capabilities and Limitations,” “Claude Code 101.” Claude’s Learning mode and Claude Code’s Learning output style (which leaves TODO(human) gaps for you to fill) are built-in “don’t just do it for me” switches.
  • CS50 Duck (Harvard) – an AI tutor tuned to lead students toward answers rather than giving them. Malan’s talk Teaching CS50 with AI.
  • Replit Learn – short free courses (“AI foundations,” 30 min).
  • AI Can Code. That’s Why You Should Learn (Chris Piech, Stanford) and Why should students still learn to code in the age of AI? (Hany Farid, Berkeley) – syntax is the AI’s now; problem decomposition and the intersection with your own field are the prize.

Whole curricula worth mining

  • CS50x and CS50P (Python) – CS50P weeks 0–2 are the gentlest Python on-ramp.
  • Software Carpentry lessons – free, with instructor notes; designed for 2-day workshops for adults.
  • The Odin Project: Foundations – its section order (intro → how the web works → installs → editors → command line → Git → HTML → CSS → JS) is a sensible dependency graph.
  • MIT 6.100L Lecture 1 – “what does a computer do; declarative vs imperative knowledge.”
  • Python for Everybody (Chuck Severance; free book and videos) – chapter 1 has a hardware-architecture section written for non-CS people.
  • How to Design Programs – only the design recipe (problem → signature → examples → body → tests) matters here, and it pairs well with prompting: you write the examples, the AI fills in the body.
  • Coding Train: Programming with p5.js (Dan Shiffman) – the most joyful on-ramp; the p5 web editor needs zero setup. Sonic Pi is a ten-minute “code is a medium” demo.
  • Codebar tutorials – built for ~2-hour coached workshops where every session ends with something to show.
  • Codecademy AI Builder – build first, then a “Learn” tab reverse-engineers the generated code into lessons. Worth a demo because it literally enacts “look at what got built and see how it’s put together.”

Teaching notes

(Planning material for the instructor. Students are welcome to read it.)

Read first

  1. Teaching Tech Together (Greg Wilson; free) – evidence-backed book on teaching adults programming in short workshops, by the founder of Software Carpentry. Chapters on mental models, cognitive load, designing lessons backward from exercises, live coding, and “In the Classroom.”
  2. Porter & Zingaro’s book (above) – the class premise, from two computing-education researchers. Mine its chapter order: assistant → design a function → read code → test/prompt → decompose → debug → automate.
  3. CS1-LLM: Integrating LLMs into CS1 Instruction (ITiCSE 2024) – the research version of the same course: reduce syntax, assess code explanation, testing, and decomposition; three open-ended projects in different domains.
  4. Willison’s vibe-coding post (above) – hand out the rules.
  5. CS50x Week 0 (above) – the model for the “how computers represent things” session.
  6. Technically’s frontend/backend piece (above) – the model for the “kinds of software” session.
  7. Mollick’s “Speaking things into existence” (above) – frames what students need to know to direct an AI.
  8. Abby Covert (above) – the vocabulary for “seeing structure.”

Opinionated teachers

  • Software Carpentry: Lessons Learned (Wilson) – candid: too much content, setup eats time, live coding beats slides.
  • Felienne Hermans, Why to use LLMs in CS education? and Why not to – the “use” post argues for teaching planning and concept selection separately from syntax; the “not” post lists the objections. Her book The Programmer’s Brain underpins the read-first approach. Blog moved to felienne.nl.
  • Mark Guzdial: Programming is for everyone – computing education for non-CS people is a different design problem from CS1; design from learners’ needs.
  • Learnable Programming (Bret Victor) – learners must see what a program does. Motivates Python Tutor, p5.js, and Xcode previews. Maggie Appleton’s survey of who actually implemented it.
  • Older Adults Learning Computer Programming (Philip Guo, CHI 2017) – 504 learners aged 60–85; the top frustration was jargon and sudden difficulty spikes.
  • Amy J. Ko’s free books – Critically Conscious Computing has the most on how novices form misconceptions.

Research on beginners and AI

  • The Widening Gap (Prather et al., ICER 2024) – AI helps students who already have metacognitive strategies and can impede those who don’t. The instructor live-coded with Copilot and regularly discussed its wrong answers in class.
  • Beginners Struggle to Understand LLM-Generated Code (Zi et al., 2025) – 32.5% per-task success reading LLM output. Comprehension is the bottleneck.
  • A 45-Minute Lesson on Prompt-Based Programming for End-User Programmers (Tran, Marwan & Price, 2026) – a drop-in lesson for people with no CS background; modest gains; prompting needs more practice than one session.
  • “Prompt Problems” (Denny et al., SIGCSE 2024) – exercise format: students are given a spec and must write the prompt that produces correct code.
  • Systematic review of the harms of GenAI in computing education (2025) – skim the categories (integrity, cognitive effects, trust).
  • Teaching CS50 with AI (SIGCSE 2024).

Ready-made syllabi for adult beginners

  • Intro to Coding Using Python at Worcester Public Library – a 6-session evening class for adult patrons. Codecademy failed (upsells, broken graders); a cloud IDE died under 14 logins; settled on Thonny plus a self-written manual, optional homework with a certificate, and a confirmation email a week out to cut no-shows.
  • Codebar tutorials (above) – the closest thing to published session plans.
  • General Assembly Dash – still free; project-based HTML/CSS/JS in the browser.
  • Hello Web App – Django for non-programmers; use for its tone and its “what a web app with a database is” framing, not its code.
  • Learn Enough – excellent but now paywalled.
  • Replit x Campus “Vibe Coding 101” – evidence this course is a recognized category; nothing published to mine.
  • Journalism: At colleges, the AI boom means everyone wants to dabble in computer science (AP, Aug 2026); Stanford education experts put AI into perspective.

Ideas for the six sessions (drawn from the resources above)

  • Open with representation, not syntax. CS50 Week 0’s order: inputs/outputs → binary/ASCII/RGB → abstraction → algorithms → pseudocode. Or the six Code.org videos.
  • Teach the landscape on two axes. Frontend/backend (Technically) and native/web/hybrid (AWS); Odin adds “which kind of developer works on which part.”
  • Make structure visible with existing tools before any code. DevTools Elements and Network tabs, Xcode’s view hierarchy and Accessibility Inspector, Mobbin flows; then draw it with NN/g’s sitemap vocabulary or C4’s Context/Container diagrams.
  • Unplugged network activity plus a knowledge check for how the web works (Code.org CSP Unit 2; Odin’s “describe a Google search”).
  • Show the entry point in three environments side by side. Notebook = the cell you run; Next.js = app/page.tsx; SwiftUI = @main → App → WindowGroup → ContentView. Shell episodes 1–2 are the prerequisite (what a file and a path are).
  • Reading before writing; test everything. CS1-LLM and Porter & Zingaro both put reading and decomposition ahead of writing; Willison on testing; Zi et al. on comprehension. Python Tutor is the tool.
  • Live-code with the AI and discuss its mistakes in class (Prather et al.). Claude’s Learning mode / Claude Code’s Learning output style make “tutor, not oracle” the default.
  • Hand out a responsible-vibe-coding sheet (Willison’s rules; Mollick’s “know what you want, judge the result, give feedback”).
  • Logistics from people who taught adults. Avoid jargon and difficulty spikes (Guo). Formative checks every few minutes, live coding over slides, design backward from exercises (Wilson). Have a backup environment, send a confirmation email, offer a certificate (Worcester PL).
  • End with “computing + your own field.” Piech and Farid; CS1-LLM’s three domain projects; Automate the Boring Stuff Part II as a project menu.

Balancing background, AI prompting, and coding exercises

  • The background material is the prompting curriculum. A prompt is a spec, and a non-coder’s spec is only as good as their vocabulary (“a single-page website, no login, that reads an uploaded CSV and shows a sortable table”). The information-architecture exercise and the prompt-writing exercise are the same exercise.
  • Hand-coding exists so students can read what the AI hands back: find the entry point, recognize a loop, see where data goes in, know which line to change. Reading, tracing, and modifying over writing from a blank file.
  • Rough split, interleaved within every session: ~35% background, ~45% building with AI (the first ten minutes of which is writing the description before touching an assistant), ~20% reading and tweaking code by hand.
  • One 90-minute rhythm: 25 min concept → 15 min describe the thing we’ll build → 35 min build with AI → 15 min read the result together and change one line.
  • Python in Colab as the hands-on track (zero setup, everything on one screen, “cells run top to bottom” is the simplest answer to “why does this run”); Xcode as a live demo for the kinds-of-software and where-does-it-start pillars. Swap to Swift Playgrounds for the last sessions if the group turns out to be all-Mac and app-motivated.
  • Course notebooks can live in a GitHub repo, edited locally (Claude Code can edit .ipynb files directly) and opened by students via https://colab.research.google.com/github/<user>/<repo>/blob/main/<notebook>.ipynb links.
